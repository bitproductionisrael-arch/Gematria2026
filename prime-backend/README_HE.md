# Prime Clock — חיבור השירות החי

האתר הקנוני: https://bitproductionisrael-arch.github.io/Gematria2026/prime-research.html

## מה כבר עובד בדפדפן
Play מפעיל Web Worker ומחשב ראשוניים במקטעים של 30,000. הנתונים המקומיים נשמרים ב־localStorage וממשיכים לאחר עצירה/רענון, בתנאי שהדפדפן לא ניקה את אחסונו. האימות באמצעות Lucas–Lehmer עובד למעריך ראשוני בטווח 3..1279. משתמשי האתר אינם צריכים להוריד או להתקין תוכנה.

## מה צריך להפעיל פעם אחת כדי לקבל פאנל רשת אמיתי
GitHub Pages לא מספק שרת מצב/נוכחות. לכן צור Cloudflare Worker + Durable Object מתוך התיקייה prime-backend. בעל האתר בלבד צריך להפעיל ולפרסם אותו באמצעות Cloudflare (למשל Wrangler, עם חשבון Cloudflare משלו):
```
cd prime-backend
npx wrangler deploy
```
קח את כתובת https://...workers.dev שהתקבלה, והגדר בקובץ prime-config.js:
```js
window.PRIME_CLOCK_API = "https://your-worker.workers.dev";
```
שמור ב־main; האתר יתעדכן אוטומטית דרך GitHub Pages. אין להוסיף סודות ל־GitHub Pages.

עד לפריסת השירות, הערכים "מחוברים", "סורקים" ונתוני רשת מוצגים כלא זמינים (—), **לא כאפס**. הגרף מציג נתונים מקומיים בלבד ומסומן בהתאם. השירות מתחיל איסוף נתונים ממועד הפעלתו, ולכן אינו ממציא חודש היסטורי.

## אמינות ומשמעות הנתונים
- "מחוברים": סשנים שהעבירו heartbeat ב־40 שניות אחרונות; לא מספר אנשים ייחודיים.
- "סורקים": סשנים שסימנו Play לאחרונה.
- "דווחו": טווחים שעבורם התקבל דיווח ראשון; אינם בהכרח מאומתים.
- "מוצלבים": שני דיווחים תואמים מסשנים שונים — לא תעודת ראשוניות קריפטוגרפית, ולא הגנה מפני כמה סשנים של אותו אדם.
- "טווח רציף מוצלב": רק טווחים שאושרו ברצף החל מהמספר 2; נתונים חסרים אינם נספרים כאילו בוצעו.
- התור משתמש בחכירה של 90 שניות. אם דפדפן נסגר באמצע, העבודה מוחזרת לאחר פקיעת החכירה.
- בדיקה של משפחת מרסן היא חותם עצמאי. אין כאן הוכחת ראשוניות של מועמד בן 100 מיליון ספרות.

## אבטחה ואפשרויות להמשך
השירות מגביל CORS לאתר Gematria2026; הגבלה זו לבדה **אינה** מנגנון נגד לקוחות זדוניים. לפני פרויקט ציבורי בקנה מידה גדול צריך להוסיף אימות תעודות בצד השרת, הגבלת תעבורה ו־rate limiting, מנגנון מניעת Sybil ותכנון תור יעיל יותר. API אינו חושף כתובת IP או מזהים מזהים בלוח. אין לדרוש ממשתמשים להוריד קובץ, להזין אסימון או להתקין הרחבה.

## בדיקת תקינות
1. פתח את prime-research.html באתר; בדוק שהטאב מוצג.
2. לחץ Play, המתן למקטע מלא; ודא שטינגים ומונה מקומי מתעדכנים ושנקודת ההמשך שורדת רענון.
3. בדוק Lucas–Lehmer על p=31 (חותם אפס) ועל p=11 (פריק).
4. לאחר פריסת Worker, פתח את האתר בשני דפדפנים; בדוק מוני נוכחות ו־cross-check לאחר שהם סורקים את אותו מקטע בשני סשנים שונים.
